## Что стало сильно (уровень лучших yii2-экстеншенов)

- **Типизация: отличный уровень.** `strict_types` везде, typed properties, union-типы, PHP 8.3 typed constants (`const string`/`const array` в DbSettingsStore.php:24-37), `match`, nullable-параметры (`?string $name = null` вместо deprecated implicit nullable). Фикс реального бага: `class Module extends Module` теперь через алиас `BaseModule`.
- **Статический анализ:** PHPStan **level 8** зелёный (для экосистемы Yii2 редкость), плюс Rector как CI-гейт и PSR-12 / PER-CS 2.0 через php-cs-fixer. Цепочка CI `cs → phpstan → rector → tests` на PHP 8.3/8.4 — правильная практика.
- **Null-safety:** все обращения к `Yii::$app` защищены, lazy-инициализация стора в Settings, честные guard-clauses вместо магии.
- **Поведенческие мелочи, реально улучшившие код:** `autoCreateTable` (продакшн не обязан автотроить схему компонентом), `data() === []` вместо `empty()`, `(string)$key` против int-ключей массива, переименование `initDatabase() -> createTable()`.

## Слабые места (по убыванию важности)

1. **События — мертвый код.** `BeforeSaveEvent`/`AfterSaveEvent` объявлены и описаны в README (`settings.beforeSave`), но нигде не диспатчатся. Документированный API, который не работает — худший вариант из возможных. Либо прокинуть `$this->trigger()` в `Settings::set()` / `AbstractSettingsModel::save()` с поддержкой `$event->cancel`, либо убрать до реализации.
2. **CacheBehavior не интегрирован и сам по себе багован.** Никто его методы не вызывает (нет хуков на события Settings), и есть несогласованность: `setToCache()` пишет поимённые ключи `settings_mod_name`, а `clearCache($module)` стирает только один ключ `settings_mod` — то есть инвалидация неполная, гарантированный stale-cache при наивном использовании.
3. **Тесты тонкие.** По одному тесту на стор (общий `testModel`). Нет round-trip get/set/delete, дефолтов, форматов кодирования, behaviors вообще. `coverage: none` в CI. Для библиотеки этого мало.
4. **Безопасность:** `unserialize($value, ['allowed_classes' => true])` (DbSettingsStore.php:225) — десериализация с разрешением всех классов. При компрометации БД это вектор; best practice — `false` или whitelist классов.
5. **Атомарность:** bulk `DbSettingsStore::set()` делает N пар delete/insert без транзакции — крах посреди цикла оставляет данные наполовину обновленными.
6. **Гигиена метаданных:** `homepage`/`support.source` в composer.json указывают на GitLab, хотя репозиторий на GitHub; версия Yii2 `^2.0.54|^22` — часть `^22` выглядит ошибочной; UPGRADE.md не упоминает новый флаг `autoCreateTable`; CHANGELOG отсутствует.

## Вердикт

Инфраструктурно (типы, статический анализ, CI, стиль) модуль сейчас **выше среднего по yii2-экосистеме**, на уровне хорошо поддерживаемых экстеншенов. Функционально — **средний**: ядро (сторы, фасад, модель) сделано аккуратно и типобезопасно, но два обещанных механизма (события, кеш) не завершены, покрытие тестами слабое. Если закрыть пункты 1–3, это будет эталонный образец для Yii2 на PHP 8.
